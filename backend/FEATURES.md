# QuoteFlow 백엔드 기능 상세 안내

이 문서는 루트 `backend/`의 실제 구현을 기준으로 작성했다. 기존 `project/`의 기능은 포함하지 않는다. 프론트엔드 없이도 Swagger에서 파일 등록부터 추출, 검토, 검색, 비교, 저장된 견적의 출력까지 실행할 수 있다.

- API 기본 주소: `http://127.0.0.1:8000`
- Swagger: `http://127.0.0.1:8000/docs`
- OpenAPI: `http://127.0.0.1:8000/openapi.json`
- 실행·환경변수 안내: [README.md](README.md)
- 개발·테스트 안내: [DEVELOPMENT.md](DEVELOPMENT.md)
- Studio 에이전트 안내: [agent_configs/README.md](agent_configs/README.md)

아래 경로는 기본 설정인 `/api` 접두사를 사용한다. `API_PREFIX`를 변경하면 해당 경로도 함께 바뀐다. `/health`는 접두사를 사용하지 않는다.

## 1. 전체 처리 흐름

```text
PDF / XLS / XLSX 등록 → 원본 파일 보관 및 견적 ID 발급
  → 별도 추출 요청 → 작업 ID 발급 → 작업 상태 조회
  → 표준 필드·품목 저장 및 정합성 검사
  → 담당자 수정·검토·확정
  → 검색 / 품목 단가 이력 / 견적 비교
  → 저장된 견적을 PDF / XLSX로 출력
```

파일 등록만으로 추출이 시작되지는 않는다. 추출 요청의 `202` 응답도 완료를 뜻하지 않는다. 프론트는 작업 ID로 완료 여부를 조회한 뒤 결과를 불러와야 한다.

| 기능 | 현재 구현 |
|---|---|
| 파일 입력 | `.xls`, `.xlsx`, 텍스트 추출 가능한 `.pdf` |
| 원본 보관 | 파일 저장, SHA-256 중복 검사, 다운로드 |
| 데이터 추출 | 로컬 규칙 기반 추출, Upstage Studio 추출 |
| 검토 | 누락·금액 불일치 경고, 수동 수정, 상태 변경 |
| 아카이브 | 목록, 복합 조건 검색, 상세, 수정 이력 |
| 관리 | 휴지통 이동·복원, 동시 수정 충돌 감지 |
| 비교 | 품목 단가 이력, 조건별 비교 |
| AI 보조 | Studio 비교 설명 |
| 출력 | 고정 양식 PDF·XLSX 다운로드 |
| 저장 | 기본 SQLite, PostgreSQL 연결 코드와 초기 스키마 |
| 연동 지원 | Swagger, CORS, 기능·설정 상태 조회, 선택적 공유 토큰 |

## 2. 파일 등록·원본 보관

### 등록 방법

`POST /api/add`에 `multipart/form-data`의 `file` 필드로 파일 하나를 보낸다. 응답에는 생성된 `quote_id`, 파일명, 상태, 버전, 상세 데이터와 중복 여부가 포함된다.

- 기본 업로드 한도는 **20MB**, PDF 한도는 **100페이지**다. 환경변수로 조정할 수 있다.
- 확장자뿐 아니라 PDF 헤더와 문서 구조, XLSX 내부 ZIP 구조도 검사한다.
- 빈 파일, 잘못된 형식, 경로 구분자·제어문자가 포함된 파일명 등을 거부한다.
- XLSX는 ZIP 항목 수·압축 해제 크기와 매크로 포함 여부도 검사한다.
- 저장 파일명은 내용의 해시를 사용한다. 사용자가 보낸 파일명을 저장 경로로 직접 사용하지 않는다.
- 원본은 기본 `backend/.runtime/files/`, DB는 `backend/.runtime/quotes.db`에 남는다. 서버 재시작 후에도 유지되므로 백업할 때 함께 보관해야 한다.

### 중복 처리

같은 파일 내용은 SHA-256으로 구분한다. 활성 견적에 같은 파일이 있으면 새 견적을 만들지 않고 기존 견적과 `duplicate: true`를 반환한다. 이 경우에도 등록 경로의 HTTP 상태는 `201`이다. 같은 파일이 휴지통에 있으면 `409`로 안내하므로 기존 항목을 먼저 복원해야 한다.

이 검사는 **완전히 같은 파일 내용**을 찾는다. 파일명이 다르더라도 내용이 같으면 중복이며, 내용이 조금이라도 다른 견적서를 자동으로 같은 문서의 개정판으로 묶지는 않는다.

### 원본 다운로드

`GET /api/quotes/{quote_id}/source`로 보관된 원본을 내려받는다. 추출·수정·출력은 이 원본 파일을 덮어쓰지 않는다.

## 3. 문서 추출·표준화

### 추출 시작과 조회

```json
{
  "quote_id": "등록 응답의 quote_id",
  "provider": "auto",
  "force": false
}
```

위 본문을 `POST /api/extraction-jobs` 또는 `POST /api/extract`에 보낸다.

| provider | 동작 |
|---|---|
| `auto` | 서버의 추출 설정을 적용하고, 자동 설정에서는 Upstage 키가 있으면 Studio, 없으면 로컬 추출 |
| `local` | 외부 AI 호출 없이 문서의 표·라벨을 규칙으로 해석 |
| `upstage` | Upstage Studio 추출 에이전트 사용. 키가 없으면 요청 거부 |

`GET /api/jobs/{job_id}`로 `queued → running → completed / failed`를 확인한다. `GET /api/extract?quote_id=...`는 추출 결과 **조회 전용**이며 작업을 시작하지 않는다.

추출 결과 조회에는 현재 수정된 `extracted_fields`, 원본 텍스트 `source_text`, 원문 행 대조까지 적용한 추출 필드 `source_fields`, 추출 경고, 정합성 검사와 최근 작업이 포함된다. 담당자 수정값과 추출 당시 값을 구분해 볼 수 있다.

- 추출 중 견적은 `extracting` 상태가 된다.
- 성공하면 데이터와 품목을 저장하고 `review_required`로 바꾼다.
- 실패하면 작업의 `error`를 남기고 견적은 검토 필요 상태로 돌아간다. 기존 데이터는 유지한다.
- 이미 추출했거나 데이터가 있는 견적의 재추출에는 `force: true`가 필요하다. 재추출 성공 시 현재 편집값이 바뀔 수 있으므로 사용자에게 이를 알려야 한다.

### 파일별 처리

**XLS:** `xlrd`로 구형 Excel의 표시 시트·날짜·저장된 숫자 결과를 읽는다. 숨김 관리 시트는 제외하고 행·열 위치를 붙여 Studio용 PDF로 전달한다. 수식·매크로·외부 연결은 실행하지 않으며 저장된 결과가 없는 수식은 확인이 필요하다. 암호화·손상 파일, 30개 초과 시트, 시트당 100,000셀 초과, 텍스트 길이 제한 초과는 처리하지 않는다.

**XLSX:** 표시 시트의 셀, 표, 날짜와 수식 원문을 읽는다. 수식은 실행하거나 재계산하지 않으며 저장된 계산 결과를 활용한다. 수식 포함 경고를 남긴다. 최대 30개 시트, 시트당 100,000셀 및 텍스트 길이 제한이 있으므로 대형 문서를 무제한 처리하지 않는다. Studio 호출 시 읽어낸 내용을 PDF로 변환해 전달한다.

**PDF:** 페이지별 텍스트와 표를 추출한다. 암호화되거나 손상된 문서는 처리할 수 없다. 유효한 PDF 파일은 등록되더라도 추출 가능한 텍스트가 없는 스캔 PDF는 추출 단계에서 실패할 수 있다. 현재 OCR 기능은 없다.

**로컬 추출:** 한글·영문 라벨, 인접 셀, 품목 표 헤더를 해석한다. 정해진 규칙으로 찾으므로 업체마다 완전히 다른 임의 양식을 모두 이해하는 기능은 아니다.

### 저장하는 견적 필드

| 구분 | 필드 |
|---|---|
| 문서 | `quote_number` 견적번호, `title` 제목, `issuer_company` 발행사 |
| 거래처·담당자 | `customer_name`, `contact_name`, `contact_email`, `contact_phone` |
| 날짜 | `issue_date` 작성일, `valid_until` 유효기간, `delivery_date` 납기일 |
| 금액 | `subtotal` 공급가액, `tax_amount` 세액, `total_amount` 총액, `currency` 통화 |
| 세금 | `tax_rate` 세율, `tax_terms` 세금 원문 조건, `tax_basis` 별도/포함 |
| 거래 조건 | `discount_terms`, `payment_terms`, `delivery_terms` |
| 메모 | `notes` 문서 메모, `review_note` 담당자 검토 메모 |
| 확장 원문 | `raw_fields` 표준 필드 밖의 원문 정보 |

`tax_basis`는 `exclusive`이면 세금 별도, `inclusive`이면 세금 포함이다. 날짜 입력은 `YYYY-MM-DD`, 통화 입력은 `KRW`, `USD` 같은 대문자 3자리 코드다.

### 품목별 필드

`items` 배열에 다음 데이터를 저장한다. 한 견적당 최대 2,000개다.

| 필드 | 의미 |
|---|---|
| `item_name` | 품목명. 품목 입력 시 필수 |
| `original_item_name` | 원문 품목명 |
| `specification` | 규격 |
| `unit` | 단위 |
| `quantity` | 수량 |
| `unit_price` | 단가 |
| `amount` | 행 금액 |
| `currency` | 품목별 통화 |
| `raw_fields` | 원문 부가 정보 |

조회 응답에는 서버가 만든 `item_id`, `line_number`도 포함된다. 수정 요청의 품목 객체에는 이 조회용 필드를 보내지 않는다.

### 원문 행 대조와 품목 관계

지원하는 명시적 열 순서의 PDF와 XLS에서는 원문 품목 행으로 수량·단위·단가·금액을 대조한다. PDF의 번호 있는 행을 읽을 수 없으면 일부 행만 교체하지 않고 AI 결과와 검토 경고를 유지한다. 반복 요약은 페이지를 넘어 같은 번호·품명·숫자가 일치할 때 한 번만 저장한다. 가격 없는 사양 문구는 품목 규격에 붙인다.

품목 `raw_fields`에는 `line_type`(`standalone/group/component`), `parent_item_name`, `included_in_parent`, 원문 페이지·행 등의 근거가 들어갈 수 있다. 구성품은 검색 가능한 품목으로 보존하되 `computed_subtotal`은 상위 품목만 합산한다. 선택 옵션은 `raw_fields.selection_required`로 표시하고 합계 계산을 보류한다. AI의 대조 전 응답은 DB `extraction_raw.agent_fields`에 별도로 남긴다. PDF의 숨은 텍스트와 화면 표기가 다를 수 있어 원본 검토는 필요하다.

### 표준화 원칙

- 금액·수량은 `Decimal`로 다룬다. DB JSON과 API에서는 정밀도를 보존하기 위해 십진 문자열을 사용한다. 예: `"12500.5"`.
- 금액·수량 입력은 음수를 허용하지 않고 전체 최대 18자리, 소수 최대 4자리로 제한한다.
- 쉼표·명시적인 화폐 단위 등을 정리한다. 잘못된 숫자·음수 등 추출값은 경고와 함께 누락값으로 처리한다.
- 없는 값은 `null`로 남긴다. 통화를 무조건 KRW로, 누락 금액을 0으로, 세율을 10%로 채우지 않는다.
- 원문과 추출 당시 값은 별도로 남긴다. 담당자 편집 후에도 추출 출처를 확인할 수 있다.

## 4. 정합성 검사·담당자 검토

견적 상세의 `validation`에는 구조화된 `warnings`, 행별 계산값 `computed_item_amounts`, 합계 계산값 `computed_subtotal`, `requires_review`가 들어간다.

| 검사 | 예시 |
|---|---|
| 기본값 누락 | 거래처, 작성일, 통화가 없음 |
| 품목 정보 누락 | 품목이 없거나 규격·단위·수량·단가·금액이 없음 |
| 행 금액 불일치 | 수량 × 단가와 원문 행 금액이 다름 |
| 합계 불일치 | 행 합계와 공급가액 또는 세금 포함 총액이 다름 |
| 세금·총액 불일치 | 공급가액 + 세액과 총액이 다름 |
| 중복 가능성 | 동일한 내용의 품목 행이 반복됨 |
| 통화 혼재 | 서로 다른 통화의 품목이 섞여 있음 |
| 조건 검토 | 세금 포함 여부 불명, 별도 검토가 필요한 할인 조건 |

경고에는 `code`, `path`, `message`가 있어 프론트에서 해당 필드를 표시할 수 있다. 원본 견적의 금액은 검사 결과만으로 자동 교정하지 않으며, 중복 의심 품목도 자동 삭제하지 않는다. 진단용 합계는 통화 혼재 경고와 함께 표시될 수 있으므로 경고를 무시하고 결제 금액으로 사용하면 안 된다.

현재 `requires_review`는 항상 `true`다. 이는 사람의 검토가 필요하다는 설계 표시이며, 견적 상태가 `confirmed`인지 판단하는 값이 아니다.

### 수정

`PATCH /api/quotes/{quote_id}` 또는 `PATCH /api/edit/{quote_id}`를 사용한다.

```json
{
  "expected_version": 3,
  "customer_name": "예시상사",
  "contact_phone": null,
  "review_note": "거래처와 금액 확인 완료"
}
```

- 보내지 않은 필드는 유지하고, 명시적 `null`은 값을 비운다.
- `items`를 보내면 품목 전체를 교체한다. 품목 하나만 보내면 나머지 품목은 유지되지 않는다. 빈 배열 또는 `null`은 품목을 비운다.
- `raw_fields`도 전달 시 해당 객체 전체를 교체하며 `null`은 빈 객체로 정리한다.
- 현재 화면에서 받은 `version`을 `expected_version`으로 보내면 오래된 화면의 수정은 `409`로 차단한다.
- 변경 내용이 있으면 다시 `review_required`가 된다. 견적 수정은 입력 금액을 유지하며 자동으로 다시 계산하지 않는다.
- 정의되지 않은 필드를 보내면 `422`다. 상세 응답 전체를 수정 본문으로 그대로 보내지 않는다.

### 상태 관리

`GET /api/status/{quote_id}`로 조회하고, `POST /api/status/{quote_id}`에 `status`, 선택적 `note`, `expected_version`을 보낸다.

| 상태 | 의미 |
|---|---|
| `review_required` | 검토 필요 |
| `extracting` | 추출 중. 추출 작업만 설정 가능 |
| `confirmed` | 담당자가 확인한 견적 |
| `rejected` | 반려한 견적 |
| `archived` | 보관 상태인 견적 |

추출 중에는 수정·상태 변경·삭제 등의 충돌 작업을 막는다. 나머지 상태 사이에는 추가 승인 절차나 엄격한 상태 전이 제한이 없다. `confirmed`로 바꾸는 요청이 경고를 자동 해결하거나 모든 필드의 정확성을 보증하지는 않는다.

`kind`와 `status`는 별개다. 새로 등록한 견적의 종류는 `archive`다. 기존 데이터 호환을 위해 과거 `draft` 값과 연결 정보는 보존하지만 초안 생성·AI 제안 API는 제거했다. `status: archived`는 휴지통이 아니며 일반 목록에 남는다.

## 5. 목록·검색·상세·품목 이력

### 목록 및 검색

- `GET /api/cards`: 목록. `status`, `kind`, `limit`, `offset` 지원.
- `GET /api/search?keyword=...`: 간단한 키워드 검색.
- `POST /api/search`: 아래 조건을 조합한 검색.

```json
{
  "customer_name": "예시",
  "item_name": "모니터",
  "date_from": "2026-01-01",
  "date_to": "2026-12-31",
  "amount_min": "100000",
  "amount_max": "5000000",
  "status": "confirmed",
  "kind": "archive",
  "limit": 20,
  "offset": 0
}
```

추가로 `keyword`, `contact_name`을 지원한다. 여러 조건은 AND로 적용한다. 날짜는 작성일, 금액은 총액 기준이다. 날짜·금액 필터를 사용하면 해당 값이 없는 견적은 제외한다. 시작일이 종료일보다 늦거나 최소 금액이 최대 금액보다 크면 거부한다.

문자열은 공백을 제거하고 대소문자를 통일한 부분 일치 방식이다. 전체 키워드는 표준 필드와 `raw_fields`를 포함한 데이터에서 찾는다. 자연어 질의 해석, 의미 검색, 벡터 검색, 유사 철자 검색은 구현하지 않았다.

목록 응답 형식은 `{ "items": [...], "total": 0, "limit": 20, "offset": 0 }`이다. `total`은 페이지를 자르기 전 개수이며 기본 20개, 최대 100개다. 최신 등록순으로 정렬하고 휴지통 문서는 제외한다.

목록 항목에는 ID, 견적번호, 제목, 거래처, 담당자, 작성일, 총액, 통화, 상태, 품목 수, 원본 파일명, 종류, 버전, 생성 시각이 들어간다. 전체 품목과 검토 경고는 상세 API로 받는다.

### 상세 및 품목 단가 이력

`GET /api/quotes/{quote_id}`는 모든 표준 필드, 품목, 메타데이터, 추출 상태, 정합성 검사 결과를 반환한다.

`GET /api/items/history?keyword=모니터`는 품목명으로 과거 단가 기록을 찾는다. 수량·단가·금액과 함께 거래처, 작성일, 결제·납품·할인·세율 조건, 연결 견적 ID를 제공한다. 휴지통을 제외한 저장 품목을 반환한다. 과거에 저장한 항목도 남으므로 `kind`와 `status`를 확인한다. 이 API도 `limit`, `offset`을 지원한다.

현재 일부 검색과 품목 이력 필터는 데이터를 읽은 뒤 Python에서 처리한다. MVP 규모의 구현이며 대규모 문서 검색 성능을 검증한 상태는 아니다.

## 6. 견적 비교

`POST /api/compare`는 AI 없이 저장된 수치를 정확히 계산하는 비교다.

```json
{
  "quote_ids": ["견적 A의 ID", "견적 B의 ID"],
  "item_name": "모니터"
}
```

- 서로 다른 견적 ID 2~10개를 받는다. `item_name`은 선택 조건이다.
- 정규화한 품목명·규격·단위·통화가 모두 일치하고 단가가 있는 품목끼리 비교한다.
- 같은 견적 안의 두 행을 서로 다른 견적처럼 비교하지 않는다.
- 단가 차이와 기준 단가 대비 증감률을 계산한다. 기준 단가가 0이면 증감률을 계산하지 않는다.
- 수량, 작성일, 결제·납품·할인·세금 조건 차이와 불명확한 조건을 함께 표시한다.
- 결과는 비교 가능한 `comparable`, 조건 확인이 필요한 `conditional`, 비교쌍이 없는 `insufficient_data`로 구분한다.

이름이 같은 제품의 실제 모델 동일성을 보장하지 않는다. 단위 변환, 환율 적용, 최저가 자동 채택도 하지 않는다. 조건이 다른 견적의 숫자만 보고 구매 결정을 내리는 기능은 아니다.

## 7. Upstage Studio AI 보조 기능

추출 외에 비교 설명 에이전트를 연결했다. 설정과 내보낸 에이전트 구성은 [agent_configs/README.md](agent_configs/README.md)에서 확인한다.

```json
{
  "kind": "compare",
  "quote_ids": ["견적 A의 ID", "견적 B의 ID"]
}
```

`POST /api/agent-runs`에 위 본문을 보내고 반환된 작업을 `GET /api/jobs/{job_id}`로 조회한다.

| kind | 입력 및 결과 |
|---|---|
| `compare` | 견적 2~5개. AI 비교 설명과 서버의 계산 기반 `verified_comparison` 제공 |

AI 비교 작업은 입력 당시 데이터 스냅샷을 사용한다. 응답 JSON 구조를 검사하지만 모델 판단의 업무상 정확성을 보증하지 않는다. 비교 결과와 계산 근거를 담당자가 확인해야 한다.

### 외부 호출 처리

- 서버가 `.env`의 키로 파일 업로드 → 에이전트 실행 → 상태 폴링 → 결과 읽기를 처리한다.
- 기본 대기 한도는 180초, 폴링 간격은 2초다. 환경변수로 조정할 수 있다.
- 조회의 일시적인 `429`, 서버 오류는 대기 한도 안에서 재시도한다. 중복 실행을 피하기 위해 생성 POST는 자동 재시도하지 않는다.
- 이번 호출에서 업로드한 외부 임시 파일은 정리를 시도한다. 성공 여부를 결과 메타데이터로 남기며 항상 삭제 성공을 보장하지는 않는다.
- API 키나 외부 오류의 민감한 응답 본문은 사용자 오류 메시지에 노출하지 않는다.
- Studio 기능을 사용할 때 문서 내용이 외부 서비스로 전달된다. 로컬 추출·계산 비교는 Studio를 호출하지 않는다.

## 8. PDF·Excel 출력

`GET /api/quotes/{quote_id}/export?format=pdf` 또는 `format=xlsx`로 현재 저장된 내용을 다운로드한다. 생략하면 PDF다.

**PDF:** 한글 폰트를 포함한 고정 견적 양식이다. 문서 정보, 품목, 금액, 조건, 메모와 검토 상태를 출력한다. 긴 품목 표는 여러 페이지로 나누고 표 헤더와 페이지 번호를 표시한다. 출력물은 견적 아카이브 사본으로 표시한다.

**XLSX:** `견적서` 시트에 표준 필드·품목·합계·조건을 쓴다. 셀 스타일, 줄바꿈, 고정 행을 적용한다. 사용자 입력이 Excel 수식으로 실행되지 않도록 문자열로 저장한다. 금액은 문자열이며 계산 수식을 제공하는 템플릿은 아니다.

출력은 원본 파일을 편집하는 기능이 아니다. 업체별 원래 디자인 재현, 사용자 템플릿 업로드, 직인·전자서명, 이메일 전송은 구현하지 않았다. 검토 전 견적도 출력할 수 있으므로 프론트에서 경고와 상태를 함께 안내하는 것이 좋다.

## 9. 수정 이력·휴지통·동시 작업

### 수정 이력과 작업 이력

- `GET /api/quotes/{quote_id}/history`: 버전, 처리 종류, 시각, 당시 데이터 스냅샷.
- `GET /api/quotes/{quote_id}/jobs`: 해당 견적에 연결된 추출·AI 작업 목록.
- `GET /api/jobs/{job_id}`: 작업 종류, 제공자, 상태, 결과·오류, 생성·수정 시각.

견적 데이터와 품목, 이력은 DB 트랜잭션으로 함께 처리한다. 버전 검사와 SQLAlchemy의 낙관적 잠금으로 동시 수정 충돌을 감지한다. 과거 버전 조회는 가능하지만 특정 버전으로 되돌리는 API는 없다. AI 비교 작업의 견적별 작업 연결은 첫 번째 입력 견적을 기준으로 한다.

### 휴지통

`DELETE /api/quotes/{quote_id}`는 영구 삭제가 아니라 `deleted_at`을 기록하는 휴지통 이동이다. 원본 파일과 DB 기록은 남는다.

- `GET /api/trash`: 휴지통 목록.
- `POST /api/quotes/{quote_id}/restore`: 복원.
- 일반 상세·검색·비교·출력에서는 휴지통 문서를 사용할 수 없다.
- 영구 삭제 및 보관 기간에 따른 자동 삭제 기능은 없다.

### 백그라운드 실행 한계

현재 작업 실행기는 프로세스 내부 FastAPI `BackgroundTasks`다. **서버 worker는 1개로 실행해야 한다.** 재시작 시 남아 있던 대기·실행 작업은 실패 처리하고 사용자가 재시도하도록 한다. 외부 큐, 분산 worker, 작업 취소·자동 복구는 구현하지 않았다.

## 10. 통계·설정·접근 제어

### 통계

`GET /api/stats`는 휴지통을 제외하고 다음 수치를 반환한다.

| 필드 | 의미 |
|---|---|
| `document_count` | 등록 원본 견적 수 |
| `review_required_count` | 검토 필요 수 |
| `confirmed_count` | 확정 수 |
| `customer_count` | 저장된 거래처명 기준 중복 제거 개수 |
| `item_count` | 품목 수 |

상태·거래처·품목은 저장된 활성 견적을 기준으로 집계하며, 과거 데이터도 포함될 수 있다. 매출액, 발주 실적, 기간별 추세, 통화별 금액 통계는 제공하지 않는다.

### 연결 상태와 인증

- `GET /health`: DB 연결 확인을 포함한 서버 상태. 인증 대상에서 제외된다.
- `GET /api/capabilities`: 지원 확장자, 크기·페이지 한도, Upstage 설정 여부, DB 종류, 상태 목록, 인증 필요 여부. 키 자체는 반환하지 않는다.
- `API_TOKEN`을 설정하면 API에 `Authorization: Bearer <설정한 토큰>`이 필요하다. `APP_ENV=production`에서는 토큰 설정이 필요하다.
- 현재 인증은 공유 토큰이다. 사용자 가입·로그인, 조직 분리, 사용자별 데이터 권한은 없다.
- Swagger와 OpenAPI 문서 자체를 별도 인증으로 가리는 구현은 없다.
- CORS 허용 주소는 설정 가능하고 기본은 `localhost:5173`, `127.0.0.1:5173`이다.
- 로컬 `127.0.0.1` 주소는 같은 컴퓨터에서 접속하는 주소다. 다른 팀원의 컴퓨터에서 사용하려면 서버의 접근 가능한 주소·실행 호스트·CORS를 따로 맞춰야 한다.

### 저장소와 배포

기본 SQLite는 외래키와 WAL을 사용한다. PostgreSQL은 `DATABASE_URL`로 연결하며 Supabase도 직접 PostgreSQL 연결 주소를 사용한다. `supabase/schema.sql`은 빈 DB에 적용하는 초기 스키마로 RLS를 켜고 익명 정책을 만들지 않는다. 기존 DB를 변경하는 migration이나 사용자별 권한 구현은 아니다.

Dockerfile과 Compose 설정은 있고 DB·파일용 볼륨을 사용한다. **실제 외부 PostgreSQL/Supabase 연결과 Docker 이미지 실행은 검증하지 않았다.**

### 주요 오류

| HTTP 상태 | 대표 상황 |
|---|---|
| `400` | 빈 파일, 부적절한 파일명 |
| `401` | 설정된 공유 토큰이 없거나 틀림 |
| `404` | 견적·작업·원본 파일이 없거나 사용 불가 |
| `409` | 버전 충돌, 추출 중 변경, 재추출 확인 필요, 휴지통 중복 |
| `413` | 업로드 크기 초과 |
| `422` | 요청 필드·숫자·범위·파일 형식 검증 실패 |
| `503` | DB 사용 불가, 필요한 Upstage 설정 없음 |

비동기 작업이 접수된 뒤 실패하면 최초 요청은 `202`일 수 있다. 최종 성공 여부는 작업 조회의 `status`와 `error`로 판단한다.

## 12. 프론트엔드 연결 순서

1. `/api/capabilities`로 지원 파일·한도·인증 여부를 읽는다.
2. `/api/add`로 업로드하고 `quote_id`와 중복 여부를 확인한다.
3. `/api/extraction-jobs`로 추출을 요청한다.
4. `/api/jobs/{job_id}`를 주기적으로 조회하고 완료·실패를 구분한다.
5. 상세 및 추출 결과를 읽어 원문, 필드, 품목, 경고를 검토 화면에 표시한다.
6. 수정 시 조회한 `version`을 `expected_version`으로 보낸다. `409`면 최신 데이터를 다시 읽는다.
7. 담당자가 확인하면 상태를 `confirmed`로 변경한다.
8. 목록·검색·이력·휴지통 화면을 연결한다.
9. 비교 화면을 연결하고 저장된 견적의 PDF·XLSX 다운로드를 제공한다.
10. AI 비교 설명이 필요하면 Studio 작업을 추가하고 계산 결과와 구분해 표시한다.

백엔드 API는 프론트 작업 전에 사용할 수 있는 상태다. 프론트 구현 이후 실제 사용자 동선과 서버 배포 환경에서 통합 확인은 별도로 필요하다.

## 14. 확인 결과와 남은 범위

### 2026-10-16 초안 기능 제거 후 확인

초안 생성 API, AI 초안 요청, 설정·샘플을 제거했다. 회귀 테스트에는 제거된 경로의 404, AI 초안 요청의 422, OpenAPI에서 초안 생성 경로가 없는지 확인하는 검사를 포함한다. 기존 견적의 비교·PDF/XLSX 출력 검사는 유지한다. 자동 테스트 **44개 통과**, 지정 Ruff 규칙 검사 통과를 확인했다.

이전 가상 문서 기반 Studio 추출·비교 실연결 기록은 남아 있다. 이번 제거 작업에서는 유료 외부 호출을 반복하지 않는다. 모든 업체 양식의 추출 정확도를 보증하지 않으며 외부 DB와 Docker 실행도 미검증이다.

### 미구현 또는 추가 검증 대상

- `.docx`, 이미지·스캔 PDF OCR.
- 업체별 자유 양식의 완전한 추출 정확도, 모든 수식·대형 파일 지원.
- 자연어·의미 검색, 제품 모델 식별, 단위·환율 자동 변환.
- 사용자별 로그인·조직별 권한, 외부 작업 큐와 다중 worker 운영.
- 수정 이력에서 특정 버전 복구, 업로드된 별도 파일 간 개정판 자동 연결.
- 영구 삭제, 업체별 출력 템플릿, 직인·전자서명·이메일 전송.
- 매출·발주 관리 및 금액 기반 경영 통계.
- 외부 PostgreSQL/Supabase 실연결, Docker 실행, 운영 부하 시험.

운영용 비밀키는 `backend/.env` 또는 배포 환경변수에만 둔다. 이 문서나 코드, 프론트엔드, 커밋에는 키를 넣지 않는다.
