# 프론트엔드 로컬 작업 안내

## 실행

저장소 루트의 PowerShell 기준이다. Node.js와 npm이 필요하다. 저장소에 Node 버전 고정 설정은 없으므로 설치된 Vite의 지원 버전도 확인한다.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173
```

`package-lock.json` 기준으로 의존성을 설치한다. 개발 주소는 기본 요청 기준 `http://127.0.0.1:5173`이며, 포트가 사용 중이면 Vite가 다른 포트를 선택할 수 있으므로 터미널 출력을 확인한다.

다른 프론트 세션과 포트가 겹치면 실행 중인 프로세스를 종료하지 말고 별도 포트를 사용한다.

```powershell
npm.cmd run dev -- --host 127.0.0.1 --port 5174
```

## API 환경설정

아래는 현재 `vite.config.js`와 프론트 소스에서 읽는 설정이다. 필요할 때 `frontend/.env.local`에 지정한다. 기존 파일은 덮어쓰지 않는다. `*.local`은 프론트의 Git 제외 대상이다.

| 변수 | 기본값 | 용도 |
|---|---|---|
| `VITE_API_PROXY_TARGET` | `http://127.0.0.1:8000` | Vite 개발 서버가 API 요청을 전달할 백엔드 |
| `VITE_API_PREFIX` | `/api` | 개발 프록시와 클라이언트의 API 접두사 |
| `VITE_API_BASE_URL` | 빈 문자열 | 직접 호출할 API 서버 주소. 비어 있으면 같은 origin 사용 |
| `VITE_API_TOKEN` | 빈 문자열 | 현재 구현의 선택적 Bearer 토큰. 브라우저에 노출됨 |

로컬 프록시 설정 예시:

```dotenv
VITE_API_PROXY_TARGET=http://127.0.0.1:8000
VITE_API_PREFIX=/api
```

환경변수를 수정하면 Vite 개발 서버를 재시작한다. 일반적인 로컬 작업에서는 `VITE_API_BASE_URL`을 비워 두고 개발 프록시를 사용한다. 직접 다른 origin을 호출하면 백엔드의 CORS 설정도 맞아야 한다.

`VITE_*` 값은 클라이언트 번들에 포함될 수 있다. Upstage 키, DB 비밀번호 등 서버용 비밀값을 넣지 않는다. 현재 토큰 방식의 제약을 고려해 운영 인증은 별도로 설계해야 한다.

백엔드 실행 방법은 `../backend/DEVELOPMENT.md`를 참고한다. 기본 주소 기준 API 문서는 `http://127.0.0.1:8000/docs`, 헬스 체크는 `http://127.0.0.1:8000/health`다. 백엔드 미실행 시 화면 틀은 볼 수 있지만 API 기능은 실패할 수 있다.

## 빌드와 확인

`frontend/`에서 실행한다.

```powershell
npm.cmd run build
npm.cmd run preview -- --host 127.0.0.1 --port 4173
```

빌드 출력은 `dist/`다. preview는 빌드 결과 확인용이며 현재 설정의 `server.proxy`는 개발 서버에 적용된다. preview나 배포에서 API를 사용하려면 별도의 API 전달 설정 또는 빌드 시점의 `VITE_API_BASE_URL`과 CORS 설정이 필요하다.

현재 `package.json`에는 `dev`, `build`, `preview`만 있고 lint/test 스크립트는 없다. 빌드 성공만으로 API 동작과 화면 품질이 검증되지는 않는다.

변경한 기능에 해당하는 항목을 확인한다.

- 화면 이동과 활성 메뉴, 기존 화면의 레이아웃
- 데스크톱·모바일 폭에서 표, 필터, 모달, 작업 버튼
- 검색·필터·페이지 이동과 빈 결과
- API 대기·오류 안내와 중복 실행 방지
- 업로드·추출 진행 상태와 완료 후 데이터 갱신
- 입력 라벨, 키보드 조작, 포커스와 모달 닫기
- 브라우저 콘솔 오류와 실패한 네트워크 요청

실제 파일 업로드나 저장 검증에는 테스트 데이터를 사용한다. 검증한 범위와 실행할 수 없었던 항목은 작업 결과에 구분해 남긴다.

## 견적서 검토

견적서 목록에서 행, 견적번호 또는 상세 보기 버튼을 누르면 검토 창이 열린다. 체크박스는 목록 선택용이다.

- 검토 미완료 상태에서 기본 정보·품목·금액·조건·검토 메모를 수정할 수 있다.
- 수정한 경우 먼저 `수정 저장`을 누르고, 서버가 반환한 확인 사항을 다시 검토한다. 금액은 자동으로 덮어쓰거나 재계산하지 않는다.
- 원본 다운로드와 확인 사항을 참고한 뒤 검토 확인란을 선택하고 `검토 완료`를 누른다.
- 완료 상태는 서버에 저장되고 현재 목록·필터에 반영된다. 완료된 견적서를 다시 열면 읽기 전용으로 확인한다.
- 저장·완료 요청은 `expected_version`으로 동시 수정을 검사한다. 충돌 시 최신 정보를 다시 불러온 뒤 검토한다.
