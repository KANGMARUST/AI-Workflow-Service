# 프론트엔드 Codex 작업 지침

## 적용 범위와 협업

- 이 파일은 `frontend/` 하위 작업에 적용한다. 이 대화의 기본 작업 범위는 프론트엔드다.
- 작업 전 관련 코드와 Git 변경 상태를 확인한다. 다른 작업자의 변경을 덮어쓰거나 되돌리지 않는다.
- 백엔드나 공용 문서 수정이 필요하면 이유와 영향 범위를 설명하고 사용자 요청 범위 안에서 진행한다. 프론트 작업을 위해 백엔드 API를 임의로 바꾸지 않는다.
- 대화는 기본적으로 한국어 반말로 간결하게 한다. 결과물의 문구는 서비스 맥락에 맞춘다. 완료한 작업과 제안, 확인한 사실과 추정을 구분한다.

## 먼저 참고할 문서

- 실행·환경설정·검증: `DEVELOPMENT.md`
- 서비스 목적: `../docs/README.md`
- API 계약: `../docs/api-contract.md`, `../backend/README.md`
- 루트 `../README.md`와 일부 기획 문서는 초기 골격 설명이므로 현재 구현과 다를 수 있다. API 연동 시 관련 백엔드 라우트·스키마와 실행 중인 API 문서도 확인한다.

## 현재 구조

React + Vite, JavaScript JSX, 일반 CSS, `lucide-react`를 사용한다.

| 경로 | 역할 |
|---|---|
| `src/main.jsx` | React 진입점과 전역 CSS 로딩 |
| `src/App.jsx` | 공통 내비게이션, 화면 전환, 업로드·추출 흐름, 알림 |
| `src/styles.css` | 공통 레이아웃·컴포넌트·반응형 스타일 |
| `src/HomePage.jsx`, `src/HomePage.css` | 홈 대시보드 |
| `src/QuoteListPage.jsx`, `src/QuoteListPage.css` | 견적서 목록·검색 |
| `src/QuoteReviewDialog.jsx`, `src/QuoteReviewDialog.css` | 견적 상세·수정 저장·검토 완료·원본 다운로드 |
| `src/quoteApi.js` | 견적 목록·검토 화면의 인증 포함 API 요청 |
| `src/PriceComparison.jsx`, `src/PriceComparison.css` | 단가 비교 |
| `src/Customers.jsx`, `src/Customers.css` | 거래처 관리 |
| `src/Items.jsx`, `src/Items.css` | 품목 관리 |
| `vite.config.js` | React 플러그인과 개발 API 프록시 |

현재 화면 전환은 `App.jsx`의 상태로 처리하며 별도 라우터를 사용하지 않는다. 홈의 초기 견적 데이터에는 샘플이 있고, 다른 화면에는 API 연동이 있으므로 수정 대상의 데이터 출처를 먼저 확인한다.

## 구현 원칙

- 기존 컴포넌트·CSS·아이콘·한국어 UI 표현을 우선 활용한다. 요청 없이 디자인 체계, 라우터, 상태관리 도구, TypeScript를 도입하지 않는다.
- 화면별 스타일은 해당 CSS에 두고 공통 스타일 변경 시 다른 화면에 미치는 영향을 확인한다. 중복 CSS 덮어쓰기를 계속 추가하기보다 해당 규칙을 정리한다.
- 변경 범위에 필요한 만큼만 컴포넌트를 분리한다. 일회성 동작을 위해 범용 추상화나 의존성을 추가하지 않는다.
- API 요청의 로딩·성공·빈 결과·실패 상태를 구분한다. 실패를 샘플 데이터나 성공 알림으로 숨기지 않는다.
- 업로드·저장·추출 중에는 중복 실행을 막고, 실패 시 사용자가 다음 행동을 알 수 있게 안내한다. 장시간 추출 작업의 진행 상태를 유지한다.
- 버튼·입력·표·모달의 의미 있는 HTML과 라벨, 키보드 조작, 포커스 표시를 챙긴다. 좁은 화면에서 내용과 작업 버튼이 잘리지 않게 한다.
- 금액·날짜·상태 표시와 빈 값 처리는 기존 화면과 맞춘다. API에 없는 값을 임의로 만들어 저장하지 않는다.
- 비밀키나 실제 고객 문서를 소스·테스트 데이터·문서에 넣지 않는다. `VITE_*`는 브라우저에 노출되므로 서버용 비밀키를 저장하지 않는다.

## 검증과 작업 마무리

- 코드 변경 후 `frontend/`에서 `npm.cmd run build`를 실행한다. 현재 별도 lint/test 스크립트는 없다. 실행하지 않은 검증은 했다고 쓰지 않는다.
- UI 변경은 가능하면 브라우저에서 해당 화면과 데스크톱·모바일 폭을 확인한다. API 변경은 실제 연동과 오류·빈 결과 상태를 확인한다.
- 문서만 수정했다면 명령·경로·설정 이름을 실제 코드와 대조한다. 불필요하게 빌드나 테스트를 추가하지 않는다.
- 마무리에는 변경 내용, 검증 결과, 남은 제약을 간결하게 전달한다. 구조·명령·환경설정이 바뀌면 이 파일과 `DEVELOPMENT.md`도 갱신한다.
