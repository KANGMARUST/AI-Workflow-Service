# 견적 아카이브 AI — Codex CLI 작업 지침

## 시작할 때

이 폴더는 **현재 개발 중인 기존 견적서 아카이브 프로토타입**이다. 새 세션은 대화 이력을 추측하지 말고 먼저 README.md, DEVELOPMENT.md, docs/AGENT_WORKFLOW.md를 읽어 현재 코드와 검증 상태를 확인한다. DEVELOPMENT.md에는 이전 설계·실패·범위 수정 이력이 있으므로 완료 상태는 가장 최근 기록과 현재 코드로 판단한다. 대기 중인 사용자 작업을 확인하지 않고 임의의 새 기능이나 API 테스트를 시작하지 않는다. 한국어로 진행 상황과 결과를 설명한다. 새 기능은 개발 MD에 먼저 구체화하고 완료 후 구현·테스트·한계를 같은 MD에 갱신한다.

## 제품 범위와 원본 보존

- 기존 견적 원본을 DB에 보관하고 추출·정정·검색·문서별 단가 이력·항목별 조회·검토·비교를 제공한다.
- **새 견적 작성, 복사, 가격 산정, 옵션 임의 선택, 새 견적서 출력 기능을 추가하지 않는다.**
- 미기재 단가·수량·금액·VAT는 추정하지 않는다. 원본 금액과 계산 진단을 분리한다. 모든 옵션과 패키지·세부 부품을 보존한다.
- 원본 파일, 최초 추출 스냅샷, 사용자 정정, 이력, 사람의 검토 완료 상태를 보존한다. AI 보고서는 agent_runs에 별도로 저장하고 원본을 자동으로 수정하지 않는다.
- 기존 사용자 DB·원본 자료를 테스트용으로 초기화하거나 교체하지 않는다. 삭제는 휴지통/복원 흐름을 사용한다. 테스트는 tests/.runs의 임시 DB로 한다.
- PDF 인적 사항의 로컬 보강은 화면에 보이는 OCR 정보를 기준으로 한다. 가려진 숨김 연락처를 복원하지 않는다.

## 구조와 실행

- backend/: FastAPI, SQLAlchemy, SQLite 기본·PostgreSQL 선택. app.py는 API, domain.py는 원본 및 데이터 저장, extraction.py는 추출, user_agent.py는 요청별 Upstage API, agent_workflow.py는 검토·비교 보고서.
- frontend/: React/Vite. src/App.jsx는 보관함·API 설정, src/AgentWorkspace.jsx는 Studio 에이전트 작업실.
- agent_configs/: 실제 Studio에서 내보낸 견적 에이전트 설정 JSON.
- backend/storage/quotes.db와 backend/storage/files/: 실제 사용자 보관 데이터. .runtime/: 서버 상태·로그. .backups/: 데이터 백업.
- Windows CMD에서 웹 실행: `start.cmd`, 종료: `stop.cmd`. 웹 http://127.0.0.1:5173, API http://127.0.0.1:8000. 이미 실행 중인 서버를 중복 시작하지 않는다.
- PowerShell 실행 정책을 바꾸지 말고 .cmd 진입점을 사용한다. launcher.mjs가 설치된 런타임을 찾으며 숨김 개발 서버를 관리한다.
- 프로젝트 codex.cmd는 직접 실행하면 이 폴더를 작업 루트로 사용하고, 저장소 루트 진입점에서 호출하면 QUOTE_CODEX_WORKSPACE의 현재 GitHub 저장소를 작업 루트로 사용한다. 기존 기본 gpt-6.1-sol은 이 계정의 CLI에서 미지원 응답을 받아 이 진입점에서만 gpt-6-sol을 적용한다. `/model` 또는 `codex -m ...`으로 사용 가능한 모델을 선택할 수 있다. 전역 Codex 설정·앱 모델·보안 옵션을 임의로 변경하지 않는다.

## 해커톤 에이전트와 API

사용법의 기준은 https://ku-sejong-hackathon-playbook.vercel.app/ 이다. '에이전트 적극 활용'은 **Upstage Studio 문서 에이전트가 실제로 추출·분류·검토·비교한다**는 뜻이며 코딩 도우미 사용 횟수와 구별한다.

현재 생성 계정의 Config ID는 모두 1:

| 역할 | Agent ID |
|---|---|
| 견적 추출 | agt_WUmdoTPSummj3uQ7Qdi6dM |
| 견적 검토 | agt_3meY3NJetTYi7X9n8RTPpB |
| 견적 비교 | agt_R5gPHUeVuUoDCheCftTnDL |

생성 상태·스키마·실연결 응답과 한계는 docs/AGENT_WORKFLOW.md에 있다. 다른 사용자 계정은 접근 가능한 자신의 Agent ID를 입력해야 한다. 원본 재추출은 PDF·Excel·Word·이미지 원본을 입력하고, 검토·비교는 보관 데이터로 조립한 중간 PDF를 입력한다. 중간 PDF는 새로운 견적서가 아니다.

배포 앱은 사용자가 웹에 입력한 키를 현재 탭 메모리와 해당 분석 요청 헤더에서만 사용한다. 서버 환경·개인 파일의 키를 공용 키로 읽지 않는다. 소스·DB·MD·로그·브라우저 저장소에 실제 API 키를 남기지 않는다. 에러·진단 출력에서도 키와 인증 파일 내용을 출력하지 않는다.

사용자는 필요한 실연결 테스트에 자신의 API를 사용하는 것을 허용했다. 필요할 때만 개발 테스트용 tests/live_quote_agents.py를 사용하고, ../Test_input_data의 가상 견적을 전송한다. 이 테스트 스크립트는 허가된 개인 키를 메모리로 읽으며 배포 서버에서 import하지 않는다. SaveAPI.md를 문서·소스에 복사하거나 광범위한 검색 출력에 포함하지 않는다. 실제 회사 견적을 외부 테스트 자료로 사용하지 않는다. 모의 결과를 실제 API 실행 이력으로 등록하지 않는다.

## 검증

변경 범위에 맞게 필요한 검증만 실행한다. 원본·DB·API·추출 동작 변경은 해당 회귀 검증을 포함한다. UI 변경은 빌드와 실제 브라우저 확인을 한다. 개발 서버를 중지할 때 다른 프로젝트나 테스트 프로세스를 일괄 종료하지 않는다.

codex.cmd가 설정한 Python/Node 또는 설치된 정상 런타임을 사용한다. 기본 CMD 명령:

```cmd
python tests\test_user_agent.py
python tests\test_agent_workflow.py
python tests\test_integration.py
cd frontend
npm.cmd run build
```

테스트 결과는 tests/*results.json, UI 증거는 tests/qa에 저장한다. 실제 API 검증은 호출 횟수·입력·응답 ID·기대값과 한계를 MD에 기록하되 키는 제외한다. 이번 CLI 설정만 검증할 때는 웹 기능 전체 테스트나 실 API 호출을 반복하지 않는다.

## 브라우저 도구

CLI의 `/mcp`에서 활성 도구를 확인한다. 이 컴퓨터에는 cua_repl이 설정돼 있지만 실제 브라우저 연결 상태는 세션에서 확인해야 한다. 도구 문서와 현재 화면을 확인한 뒤 Studio를 조작하고, 완료 시 생성·저장 결과를 확인한다. 기존 별도 장사비서/HR 에이전트는 수정하지 않는다. CLI에서 브라우저를 제어할 수 없으면 설정 JSON을 준비하고 현재 앱 또는 Studio의 설정 가져오기로 이어간다. 도구 사용 성공 없이 브라우저 작업 완료를 주장하지 않는다.

### 웹 제어 실패 시 GPT Work 요청 프롬프트 제공

**웹을 이용하여 에이전트를 구축해야 하는 상황에서 웹 제어에 실패하면, GPT Work에 해당 작업을 요청할 수 있는 프롬프트를 사용자에게 제공한다.**

먼저 도구 연결과 실패 원인을 확인하고 가능한 복구를 시도한다. 웹 제어가 불가능하거나 사용자 조작이 필요한 상태라면 실패·미완료 상태를 명확히 설명하고, 사용자가 GPT Work에 그대로 복사해 붙여넣을 수 있는 완성된 요청문을 작성한다. 단순히 'GPT Work에 요청하세요'라고 끝내거나 빈칸 위주의 양식을 주지 않는다. 요청문에는 해당 시점에 확인한 실제 작업 내용을 채운다.

요청문에 포함할 내용:

- 기존 견적 아카이브라는 프로젝트 목적과 이번 에이전트 생성·수정 목표.
- Studio 주소 https://studio.upstage.ai/ 와 사용 가이드북 https://ku-sejong-hackathon-playbook.vercel.app/ .
- 대상 에이전트 이름·역할·확인된 Agent ID·Config ID, 새로 만들 대상과 보존할 기존 에이전트.
- 필요한 노드 연결, 분류 기준, 분기별 추출 스키마의 필드명·유형·목록 여부와 입출력 예시.
- CLI에서 완료한 준비, 실제 실패 원인과 아직 남은 단계. 미확인 값은 추정하지 않고 미확인으로 표시.
- 필요한 설정 JSON·가상 테스트 파일의 이름과 위치. GPT Work가 로컬 경로에 접근할 수 있다고 가정하지 말고, 필요한 스키마·설정 내용은 요청문에 포함하거나 사용자가 첨부해야 할 파일을 명시.
- 완료 확인 기준: Studio 생성/저장 확인, 가상 문서 결과 JSON 검증, Agent ID·Config ID 확인 및 설정 JSON 내보내기. CLI에 돌아와 연결할 파일과 변경 정보를 반환하도록 요청.
- 원본 금액·옵션·기존 문서 및 별도 장사비서/HR 에이전트 보존 원칙. 실제 API 키·인증값·회사 기밀은 요청문에 포함하지 않는다.

사용자가 요구한 것은 **전달용 프롬프트 제공**이다. 별도 사용자 지시 없이 GPT Work 채팅을 만들거나 다른 채팅에 메시지를 자동 전송하지 않는다. 웹 작업이 막혀도 준비할 수 있는 설정 파일·연결 코드·개발 기록은 진행하며, 생성 여부를 확인하기 전에는 완료로 기록하지 않는다.

## 보고

완료 결과, 검증 방법과 실패·미검증 상태를 간단히 설명한다. 기록을 갱신하고 파일 위치를 알려준다. 프로토타입의 로그인/사용자 문서 권한 분리는 아직 구현되지 않았으므로 BYOK만으로 배포 사용자 문서가 격리됐다고 주장하지 않는다.
