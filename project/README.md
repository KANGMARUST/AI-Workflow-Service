# 견적 아카이브 AI

**기존에 발행한 견적서를 검색 가능한 데이터베이스로 정리하는 로컬 프로토타입입니다.**

파일을 등록하면 거래처·담당자·연락처·제목·품목·수량·단가 등 정보를 추출합니다. 원본과 대조하여 추출 오류를 정정하고, 조건 검색으로 목록·상세·원본을 조회합니다.

새 견적 작성·복사·가격 산정·양식 관리·새 견적 파일 출력은 현재 범위에서 제외했습니다. 개발 기준과 완료 결과는 [DEVELOPMENT.md](DEVELOPMENT.md)를 확인하십시오.

## 실행
현재 컴퓨터에는 라이브러리가 설치되어 있습니다. PowerShell에서 이 폴더로 이동한 뒤:
```powershell
.\start.cmd
```
[앱 열기](http://127.0.0.1:5173). 종료는 `.\stop.cmd`.

처음 설치하는 컴퓨터에서는 Node24/npm11/Python3.12 이상을 준비한 뒤 `.\setup.cmd`를 실행합니다. Python 실행 파일은 `QUOTE_PYTHON` 환경변수로 지정할 수 있습니다. 수동 실행은 두 터미널에서 각각:
```powershell
# 백엔드
cd backend
python run.py
# 별도 터미널의 프론트
cd frontend
npm.cmd run dev
```
백엔드8000, 프론트5173. 실행 로그는 .runtime/, 데이터는 backend/storage/quotes.db와 files/에 보관합니다.

PowerShell에서 `running scripts is disabled` 오류가 나면 `.ps1` 대신 위 `.cmd` 파일을 사용하세요. 실행 정책과 관리자 권한을 변경하지 않습니다. `launcher.mjs`가 서버를 숨김 실행하고, 기록한 PID·프로젝트 경로·생성 시각이 일치하는 서버만 종료합니다. 기존 `.ps1` 파일은 스크립트 실행을 허용한 환경의 선택 실행 방법으로 유지합니다.

## 시연
1. 견적 보관함의 **data 자료 불러오기**로 PDF2개·XLS1개를 실제 분석·등록합니다.
2. 제목·거래처·담당자·품목·기간 등으로 검색합니다.
3. 결과에서 상세를 열어 원본·추출 내용·모든 품목과 조건을 확인합니다.
4. 추출 오류가 있으면 정정 저장 후 원본의 불명확한 항목을 확인하고 **검토 완료**합니다.
5. 품목 이력에서 거래처별·시기별 원본 단가와 규격·수량·통화를 확인합니다.

원본은 수정하지 않습니다. 문서의 모든 선택 옵션과 패키지·부품 관계를 보존합니다. 옵션을 선택해 새 합계를 만들지 않습니다. 원본 VAT별도에 세율·세액이 없으면 임의10%/세금포함총액을 만들지 않습니다. 숫자합계가 없는 문서는 **원본 합계 미기재**로 표시합니다.

## 기능
- PDF/XLS/XLSX/DOCX/PNG/JPG 다중 등록, 부분 실패 안내, 중복 방지, 원본 연결
- 거래처·담당자·고객 참조 담당자·연락처·제목·품목·견적번호·기간·원본금액·검토 상태 검색
- 견적 목록/상세/원문/원본, 추출 오류 정정·검토 완료·정정 이력
- 원본 옵션·부품을 포함한 품목 이력/단가 조회
- 문서수·검토 필요·거래처수·품목수 현황
- 업무 조건을 해석하는 자연어 검색 보조

## 데이터·환경
data/는 사용자 Input_data 원본을 복사한 로컬 자료이며 gitignore 대상입니다. 사용자 원본과 기존 DB 자료는 삭제하지 않습니다. 이전 버전에서 만든 복사 시연 자료는 DB에 보존하면서 아카이브 목록·검색에서는 제외합니다. 범위 변경 전 DB는 .backups/에 백업했습니다.

기본은 로컬 구조 추출·한국어 OCR·SQLite입니다. backend/.env.example과 frontend/.env.example으로 환경을 설정할 수 있습니다. DATABASE_URL로 PostgreSQL/Supabase 연결을 선택합니다. 외부 AI는 EXTERNAL_AI_ENABLED와 키를 운영자가 명시 설정했을 때만 호출하며 기본 실행에서는 원본을 원격 전송하지 않습니다. 실제 Supabase·외부 AI 접속과 Docker 실행은 현재 환경에서 검증하지 않았습니다.

Docker 환경을 준비한 컴퓨터에서는 `docker compose up --build`로 두 서버를 실행할 수 있습니다. 로컬 OCR 모델은 backend/models에 동봉되어 있습니다.

PDF에서 화면에 가려진 정보가 내부 텍스트에 남을 수 있어 숨김 연락처·대표자 행을 마스킹하고 원본 확인을 요구합니다. 임의 양식이나 저해상도 사진은 담당자 검토가 필요합니다.

## 검증
아카이브 범위의 통합 테스트 **11개 모두 통과**, 실패·오류 0입니다. 기존 생성·출력 테스트는 tests/archive/에 이전 이력으로 보관하며 현재 기능의 검증으로 사용하지 않습니다. 최신 결과는 tests/integration-results.json, 상세 범위는 DEVELOPMENT.md에 기록했습니다. frontend production build와 실제 브라우저의 담당자·제목 검색, 원본 상세 및 전체 옵션 품목 이력도 확인했습니다.

```powershell
python tests/test_integration.py
```
테스트는 별도 임시DB·서버를 사용하므로 사용자 자료를 변경하지 않습니다.
