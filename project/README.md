# 견적 아카이브 AI

**기존에 발행한 견적서를 검색 가능한 데이터베이스로 정리하는 로컬 프로토타입입니다.**

파일을 등록하면 거래처·담당자·연락처·제목·품목·수량·단가 등 정보를 추출합니다. 원본과 대조하여 추출 오류를 정정하고, 조건 검색으로 목록·상세·원본을 조회합니다.

새 견적 작성·복사·가격 산정·양식 관리·새 견적 파일 출력은 현재 범위에서 제외했습니다. 개발 기준과 완료 결과는 [DEVELOPMENT.md](DEVELOPMENT.md)를 확인하십시오.

## 실행
개발을 Codex CLI로 이어가려면 이 project 폴더의 CMD에서 `codex`를 입력한다. 현재 프로젝트 지침은 AGENTS.md가 안내하며 실행 설정·검증 결과는 [docs/CLI_SETUP.md](docs/CLI_SETUP.md)에 있다.

현재 컴퓨터에는 라이브러리가 설치되어 있습니다. PowerShell에서 이 폴더로 이동한 뒤:
```powershell
.\start.cmd
```
[앱 열기](http://127.0.0.1:5173). 종료는 `.\stop.cmd`.

처음 설치하는 컴퓨터에서는 Node24/npm11/Python3.12 이상을 준비한 뒤 `.\setup.cmd`를 실행합니다. Python 실행 파일은 `QUOTE_PYTHON` 환경변수로 지정할 수 있습니다. 수동 실행은 두 터미널에서 각각:
```powershell
# 백엔드
cd backend
python run.py
# 별도 터미널의 프론트
cd frontend
npm.cmd run dev
```
백엔드8000, 프론트5173. 실행 로그는 .runtime/, 데이터는 backend/storage/quotes.db와 files/에 보관합니다.

PowerShell에서 `running scripts is disabled` 오류가 나면 `.ps1` 대신 위 `.cmd` 파일을 사용하세요. 실행 정책과 관리자 권한을 변경하지 않습니다. `launcher.mjs`가 서버를 숨김 실행하고, 기록한 PID·프로젝트 경로·생성 시각이 일치하는 서버만 종료합니다. 기존 `.ps1` 파일은 스크립트 실행을 허용한 환경의 선택 실행 방법으로 유지합니다.

## 시연
1. 견적 보관함의 **data 자료 불러오기**로 PDF2개·XLS1개를 실제 분석·등록합니다.
2. 제목·거래처·담당자·품목·기간 등으로 검색합니다.
3. 결과에서 상세를 열어 원본·추출 내용·모든 품목과 조건을 확인합니다.
4. 추출 오류가 있으면 정정 저장 후 원본의 불명확한 항목을 확인하고 **검토 완료**합니다.
5. 품목 이력에서 거래처별·시기별 원본 단가와 규격·수량·통화를 확인합니다.

원본은 수정하지 않습니다. 문서의 모든 선택 옵션과 패키지·부품 관계를 보존합니다. 옵션을 선택해 새 합계를 만들지 않습니다. 원본 VAT별도에 세율·세액이 없으면 임의10%/세금포함총액을 만들지 않습니다. 숫자합계가 없는 문서는 **원본 합계 미기재**로 표시합니다.

## 기능
- PDF/XLS/XLSX/DOCX/PNG/JPG 다중 등록, 부분 실패 안내, 중복 방지, 원본 연결
- 거래처·담당자·고객 참조 담당자·연락처·제목·품목·견적번호·기간·원본금액·검토 상태 검색
- 견적 목록/상세/원문/원본, 추출 오류 정정·검토 완료·정정 이력
- 원본 옵션·부품을 포함한 품목 이력/단가 조회
- 문서수·검토 필요·거래처수·품목수 현황
- 업무 조건을 해석하는 자연어 검색 보조

## 데이터·환경
data/는 사용자 Input_data 원본을 복사한 로컬 자료이며 gitignore 대상입니다. 사용자 원본과 기존 DB 자료는 삭제하지 않습니다. 이전 버전에서 만든 복사 시연 자료는 DB에 보존하면서 아카이브 목록·검색에서는 제외합니다. 범위 변경 전 DB는 .backups/에 백업했습니다.

기본은 로컬 구조 추출·한국어 OCR·SQLite입니다. backend/.env.example과 frontend/.env.example으로 환경을 설정할 수 있습니다. DATABASE_URL로 PostgreSQL/Supabase 연결을 선택합니다. 외부 AI는 웹의 API 설정에서 사용자가 자신의 Upstage API Key·Agent ID·Config ID를 적용하고 전송에 동의했을 때만 PDF 파일 등록 요청에 사용합니다. 서버 공용 키와 개인 키 파일은 사용하지 않습니다. 실제 Supabase·외부 AI 접속과 Docker 실행은 현재 환경에서 검증하지 않았습니다.

Docker 환경을 준비한 컴퓨터에서는 `docker compose up --build`로 두 서버를 실행할 수 있습니다. 로컬 OCR 모델은 backend/models에 동봉되어 있습니다.

PDF에서 화면에 가려진 정보가 내부 텍스트에 남을 수 있어 숨김 연락처·대표자 행을 마스킹하고 원본 확인을 요구합니다. 임의 양식이나 저해상도 사진은 담당자 검토가 필요합니다.

## 검증
아카이브 범위의 통합 테스트 **11개 모두 통과**, 실패·오류 0입니다. 기존 생성·출력 테스트는 tests/archive/에 이전 이력으로 보관하며 현재 기능의 검증으로 사용하지 않습니다. 최신 결과는 tests/integration-results.json, 상세 범위는 DEVELOPMENT.md에 기록했습니다. frontend production build와 실제 브라우저의 담당자·제목 검색, 원본 상세 및 전체 옵션 품목 이력도 확인했습니다.

```powershell
python tests/test_integration.py
```
테스트는 별도 임시DB·서버를 사용하므로 사용자 자료를 변경하지 않습니다.

### 추가 정보 보존과 삭제

견적 상세의 **추가 정보와 문서 조건**에서 주소·보증·비고 등 추가 내용을 정정하거나 보완할 수 있습니다. **문서 전체 내용**에서 PDF 페이지 원문·표, Excel 시트의 셀·수식·메모, Word 본문·표를 펼쳐 확인하세요. 이미지·도장·서식은 원본 파일에서 확인합니다.

견적 보관함 표의 **삭제** 버튼을 누르고 문서명을 확인한 뒤 **휴지통으로 이동**을 선택하세요. 좁은 화면에서는 표를 오른쪽으로 스크롤하면 삭제 열이 보입니다. 삭제한 문서는 검색과 단가 이력에서 제외되며, 왼쪽 **휴지통 → 복원**으로 되돌릴 수 있습니다. 원본 파일과 저장 정보·정정 이력은 보존됩니다.

### 세부 정보와 인적 사항

견적 상세의 **세부 항목별 저장 정보**에서 회사·고객·견적 식별·거래 조건과 CPU·메모리·운영체제 등 품목 사양을 항목별로 확인하세요. 원문 위치도 표시됩니다.

**문서의 모든 인적 사항**에서는 인물별 이름·회사·부서·직함·역할·전화·휴대전화·이메일·팩스·주소를 확인하고 정정할 수 있습니다. 누락된 사람은 **인적 사항 보완**으로 추가하고 **추출 정보 정정 저장**을 누르세요. 인적 사항 추출 원문과 PDF 화면 전체 OCR 원문을 펼쳐 비교할 수 있습니다. 이름 미확인 연락처는 원본을 확인해 보완하세요. 가려진 정보는 복원하거나 추정하지 않습니다.

### 카테고리별 조회

왼쪽 **항목별 조회**를 누르고 **팩스**를 선택하면 저장된 팩스 번호 목록이 나옵니다. 전화·이메일·주소·품목 단가·CPU 등도 같은 방법으로 선택할 수 있습니다. 숫자는 저장된 항목 수입니다. 목록에서 값·인물·거래처·문서 제목을 검색하고 견적서 제목을 눌러 상세를 확인하세요. 삭제한 문서는 제외되며 휴지통에서 복원하면 다시 표시됩니다.

### 내 API 설정과 가이드북

API 설정의 **Agent ID에는 견적아카이브_추출**을 입력합니다. **Upstage API Key**는 본인 계정의 인증 키이며, 이 키로 접근 가능한 추출·검토·비교 에이전트를 실행합니다. **Agent ID**는 작업별 실행 대상이고 **Config ID**는 해당 에이전트의 설정 버전입니다. 웹의 **어떤 에이전트를 연결하나요?** 표에서 실제 이름·입력 위치·생성 계정의 ID와 Config ID 1을 확인하세요. 검토·비교 ID는 **에이전트 작업실**에서 해당 작업을 선택한 뒤 입력합니다. 다른 계정은 자신의 Studio에서 접근 가능한 역할별 ID와 버전을 확인해야 합니다.

왼쪽 **API 설정**에서 본인의 **Upstage API Key · Agent ID · Config ID**를 입력하고 외부 분석 동의를 선택한 뒤 **현재 탭에 적용**을 누릅니다. API 발급·Studio 설정·연결 오류의 사용방법은 https://ku-sejong-hackathon-playbook.vercel.app/ 를 참조하세요. 화면의 가이드북 열기와 절별 바로가기에서도 연결됩니다.

적용 후 새 PDF 파일을 등록하면 해당 사용자의 Studio 에이전트로 분석합니다. 에이전트의 JSON 출력은 DEVELOPMENT.md의 Quote/Item 항목명과 일치해야 합니다. 기본 정보 필드는 단일 값 또는 값 1개의 배열, items는 품목 객체 배열입니다. 숫자는 원문 명시값만 출력하고 누락값을 추정하지 마세요. 인적 사항은 가려진 PDF 텍스트를 복원하지 않도록 기존 화면 기반 추출·수동 검토를 유지합니다.

API 키는 현재 탭 메모리와 해당 분석 요청에서만 사용합니다. 키를 DB·.env·브라우저 저장소에 저장하거나 다른 사용자에게 공유하지 않습니다. **API 설정 지우기** 또는 새로고침으로 제거됩니다. 서버의 OPENAI_API_KEY/UPSTAGE_API_KEY 및 개인 키 파일을 API 실행에 사용하지 않습니다. PDF 외 형식과 data 자료 불러오기는 로컬 분석을 유지합니다. Upstage 전송이 발생하면 본인 계정 사용량이 발생합니다. 배포 환경은 HTTPS가 필요합니다.

현재 프로토타입의 문서 보관함은 공유되고 로그인/사용자별 문서 권한은 구현되지 않았습니다. API 키 요청 분리와 사용자별 문서 접근 권한은 별개입니다. 실제 공개 배포 전에는 인증·문서 권한을 추가하고 호스팅 로그에 요청 헤더/본문을 기록하지 않도록 설정해야 합니다. 실제 사용자 키로 Upstage 연결은 개발 과정에서 실행하지 않았으며, 테스트는 모의 API로 수행했습니다.

## Studio 에이전트 작업실

기본 화면에서 원본 PDF 재추출, 저장 견적 검토, 문서 2~5개 비교를 실행합니다. API 설정에서 본인 Upstage 키와 동의를 적용하고 작업실에서 역할별 Agent ID/Config ID를 확인하세요. 실제 생성 설정은 agent_configs, 활용·API 호출·테스트 기록은 docs/AGENT_WORKFLOW.md에 있습니다. 분석 결과는 별도 보고서이며 원본 금액을 자동 변경하지 않습니다. 다른 계정은 자신이 접근 가능한 Studio Agent ID로 바꿔야 합니다. 사용법: https://ku-sejong-hackathon-playbook.vercel.app/#sec5
