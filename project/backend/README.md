# 기존 견적서 아카이브 백엔드

이미 발행된 견적서 파일에서 정보를 추출하여 저장·검색·조회하는 로컬 프로토타입입니다. 새 견적 작성·복사·영업 상태·양식·견적서 출력 기능은 제거되었으며 관련 API는 410을 반환합니다.

## 실행

Python 3.12에서 `pip install -r requirements.txt` 후 `python run.py`를 실행합니다. 현재 컴퓨터의 번들 Python에서는 프로젝트 내부 `.packages`를 `run.py`가 자동으로 사용합니다. 기본 주소는 localhost:8000이며 `/docs`에서 API를 확인할 수 있습니다.

DB는 기본 `backend/storage/quotes.db`, 원본 파일은 `backend/storage/files/`에 저장합니다. `QUOTE_DATA_DIR`와 `QUOTE_SAMPLE_DIR`로 저장 경로와 읽기 전용 샘플 경로를 바꿀 수 있습니다. `DATABASE_URL`이 있으면 PostgreSQL/Supabase 직접 연결을 사용합니다. 실제 외부 DB 연결은 자격증명이 없어 미검증입니다. 운영용 직접 DB 역할과 접근 권한은 서버 운영자가 설정해야 합니다.

## 원본 데이터 보존

수량·단가·금액·공급가액·세액·총액은 원본 명시값과 담당자의 추출 오류 정정값을 보존합니다. 수량이나 단가를 정정해도 금액을 자동으로 변경하지 않습니다. 계산 검사는 별도 `computed_amount`, `computed_subtotal`에만 기록합니다. VAT 별도이고 원본에 세율·세액·세금 포함 총액이 없으면 해당 필드는 null입니다. 대체 옵션은 모두 저장·검색·단가 조회에 포함하며 선택이나 합계를 강제하지 않습니다. 패키지와 부품의 관계는 보존하며 진단 합계에서 중복 합산하지 않습니다.

원본 금액의 기준은 `source_total_kind`, `tax_note`로 표시합니다. 원본 합계가 “선택”이거나 미기재이면 합계를 임의 생성하지 않습니다. 원본 견적번호가 없으면 `number`는 빈 값이며 시스템 UUID는 별도 식별자입니다.

저장된 원본 파일의 연결·해시가 있는 자료만 아카이브 조회 대상입니다. 이전 구현에서 만든 수동/복사 자료는 DB에 보존하지만 목록·검색·현황·상세에서 제외합니다. 초기 실행 시 이전 추정 10%·생성금액을 원본 기준으로 환원하고 재검토 상태로 전환합니다. 기존 헤더·품목 정정값은 유지하고 이전 payload 전체를 정정 이력으로 보존합니다. 원본을 재분석해 원본 필드 snapshot을 기록하는 과정은 로컬에서만 실행됩니다.

누락·불일치·대체 옵션은 원본 확인 경고입니다. 담당자가 원본의 불명확한 부분을 검토하고 `acknowledged_warnings`로 확인하면 검토 완료할 수 있습니다. 정정하면 다시 검토 상태로 돌아가고 버전 이력을 보관합니다. 파일 자체는 변경하지 않습니다.

## 추출과 검색

PDF 텍스트, XLS/XLSX 셀, DOCX 표, PNG/JPG 로컬 OCR을 지원합니다. 공개 RapidAI 한국어 인식 모델은 `models/korean_rec.onnx`에 동봉되어 외부 OCR 전송이나 런타임 다운로드 없이 실행됩니다. OCR과 표 구조는 양식에 따라 담당자 확인이 필요합니다. PDF에서 시각적으로 가린 연락처가 숨김 텍스트에 남는 경우를 고려해 견적 담당자·연락처를 자동 채우지 않습니다. UI용 추출 원문과 과거 이력 원문에서도 연락처와 대표자 정보가 있는 줄을 마스킹합니다. 참조 고객 담당자는 별도 `customer_contact`에 저장하고 원본과 대조할 수 있습니다.

거래처·담당자/참조 담당자·연락처·제목·품목/규격·견적번호·기간·원본 금액·검토 상태를 조합 검색합니다. 자연어 검색은 저장된 데이터에 있는 조건만 해석하는 로컬 보조 기능입니다. 통계는 등록 문서·검토·거래처·저장 품목수 중심이며 금액이 없으면 합산하지 않습니다. 원본 금액 집계는 KRW 기준이고 VAT 별도·포함이 혼재할 수 있음을 표시합니다.

웹의 API 설정에서 사용자 자신의 Upstage API Key·Agent ID·Config ID를 입력하고 외부 분석에 동의하면 PDF 파일 등록에만 Studio 에이전트를 사용합니다. 키는 현재 탭의 메모리 및 해당 서버 요청에서만 사용하며 환경변수·키 파일·DB·브라우저 저장소에 공용으로 저장하지 않습니다. 새로고침 또는 API 설정 지우기로 제거합니다. 개발·검증은 모의 API로 진행하며 실제 키·사용자 원본은 외부로 보내지 않았습니다. 실연결은 미검증입니다.

이 서비스는 로그인 없는 localhost 프로토타입입니다. 업로드는 파일당 30MB까지 지원합니다. 원본·DB의 백업, 조직 권한, 운영 서비스 배포는 별도 운영 작업입니다.
